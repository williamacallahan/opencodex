# Hub usage archive: settled design (expert design after two rejected fixes, 2026-11-25)

Status: Slices 1, 1b and 2 shipped (main at `d9e2d3c20`); slices 3 and 4 remain open.

Rejected draft faa8eb6af is archived at refs/archive/1795585464-22221/branch/fsw-hub-review-fixes and saved as faa8eb6af-rejected.patch beside this file. Do not land it or port its owned-name parser, tail sampler, or untimed inode heuristic.

Core rule: for a captured ledger L = P || S (P ends at a complete row boundary), prepare an immutable archive file holding exactly P and a new live JSONL holding exactly S (torn tail included); keep the old live file untouched; after both files and both directory entries are durable, commit one catalog transaction that switches the live generation and adds the segment. Before commit readers see P||S live and no new archive; after commit they see S live and P archived exactly once. Use a small bun:sqlite catalog in a hub-private directory on the persistent archive volume (store id, current live generation, committed segments, at most one pending trim). Rows stay raw JSONL. compose.yaml:20–24 puts ledger and archive on two volumes, so no cross-volume rename.

Stop registering the archive directory as disposable. removeCanonicalOwnedConfigState reports the remaining paths via its existing partial-uninstall result.
- Invariant: no old or new uninstall manifest, retry, or background totals build writes or deletes in the legacy archive.
- Failing-first tests: tests/config/config-ownership-uninstall.test.ts and tests/usage/usage-archive-leftovers.test.ts with a legacy manifest listing directory and child; an ordinary file, an exactly valid-looking segment and totals name, a temp-looking name, a link; run trim, totals maintenance, uninstall twice; bytes, link, link target and recent live ledger survive; unrelated owned state still removed.
- Unchanged: appends, other config writes, other uninstall rules. Cost: ledger size enforcement is suspended until slice 3; measure and report the hub ledger's current size and the volume's free space and growth rate so the time to fill is known.

## Slice 2 — archive reads tell the truth
- src/usage/archive-query.ts: readArchiveListing, entryMayOverlap, segmentOverlaps distinguish committed / unknown / absent; add catalog-backed listing (no writer yet). Never drop an unknown span by filename, mtime, or one-hour slack.
- src/usage/archive-rows.ts: remove archiveStopOffset's inference from the first offset of a later hour (an in-window request can finish after it); use observed byte boundaries for the requested hours or read to segment end under the existing deadline.
- src/usage/archive-totals.ts: version the index; record coverage before attribution or hour-cap rejection (builder rejects an hour before updating extrema ~182–188).
- src/usage/archive-answer.ts, src/server/management/usage-archive-routes.ts: never serve a number as exact when an hour, attribution or overlap was dropped; return explicit incomplete/unavailable without an exact total. Pending build or missing file is not zero.
- Legacy ambiguity: crashed pre-rename copy vs published segment + restored ledger can be byte-identical; keep such files read-only and report them; never include, exclude, adopt or delete silently.
- Tests: tests/usage/usage-archive-rows.test.ts rows in order in-window, hours later, in-window again → both in-window ids returned; tests/usage/usage-archive-route.test.ts matching row in the 745th distinct hour and overlap cap exceeded with multi-attempt rows → equals raw-row oracle or declines exact total; two ambiguous untimed legacy files → neither fabricated count nor clean empty.

## Slice 3 — publish prefix and new live generation in one decision
- New src/usage/archive-catalog.ts: openArchiveCatalog, prepareTrim, commitTrim, readUsageGeneration. src/usage/log.ts: usageLogPath, appendUsageEntry, currentUsageLogRevision resolve the catalog-selected live generation once switched. ledger-retention.ts keeps firstRowBoundary, copyRange and the final revision check; replaces archiveTrimmedSpan and leftover deletion with the transaction. src/server/usage-ledger-retention.ts runs invalidateLedgerReaders on committed generation change.
- Bind the home durably to the store id before enabling; missing/mismatched mount afterwards is an error, never a fallback. Use the home-wide writer lease (src/lib/spend-ledger-owner.ts) for append and cutover. One pending op with fixed object ids; create both objects exclusively at final private names without resolving the final component; a collision is never permission to reuse/truncate/unlink; strict-sync both descriptors and directories; recheck the captured source excluding cooperating appends; commit expected-old-generation → new generation + segment. Reopen after uncertain commit reads the catalog first; retry resolves the same pending op.
- Managed directory created exclusively, identity bound to the home; refuse redirected parents; destructive maintenance only in the hub-exclusive namespace; unknown files untouched. Windows or filesystems without the durability guarantees: defer before creating or switching anything.
- Readers pin one generation per answer; caches keyed by generation/object id; /api/usage and archive routes return the same generation token and reject a stale requested one. Keep the initial usage.jsonl read-only after first cutover. Document that tools opening the literal path must use the resolved path; no mixed-version writers or downgrade on a switched home.
- Tests (tests/usage/usage-ledger-retention.test.ts): interrupt at each durable boundary incl. commit-success-before-ack; fresh-process reopen compares ordered row occurrences and raw bytes (identical rows, unknown fields, torn suffix); changed cut size, untimed head, append during prepare, destination collision, stale readers; fail each sync independently; POSIX keeps old generation on precommit failure; Windows reports unsupported and leaves bytes alone.

## Slice 4 — reclaim only proven objects
- Replace pruneUsageArchive with expireCommittedSegments in the catalog owner. While copying P compute the max timestamp over every raw row (before normalization/attribution/hour limits); retainThrough = max(sealedAt, maxRowTimestamp) + 31 days; uninspectable rows → age-unknown, retained. Never use totals lastRowAt, samples or mtime to authorize deletion.
- Commit removal from the readable generation first, then reclaim raw and derived objects after readers release them; bounded pending-deletion record; retired live files only after their replacement commit is durable; new totals live in the private store. Run bounded batches at startup and next expiry via src/server/usage-ledger-retention.ts.
- Disk bound: one live target + 31 days sealed + derived + one trim's working space at bounded input; hard budget needs admission reservation at createServeOptions (src/server/index/serve-options.ts ~290) and createWebsocketHandler (websocket-handler.ts ~106) with a proved max record size; on full budget, failed sync, unavailable mount, unknown-age backlog, or unsupported platform, refuse new work before dispatch; never evict young rows or drop a log. Legacy bytes count against capacity, never reclaimed.
- Tests (tests/usage/usage-archive-leftovers.test.ts): youngest row in the middle outside both 64-row samples and the totals hour cap with backdated mtimes; just before/at/after 31 days incl. a future timestamp; interrupt between logical expiry and unlink; reader held across expiry; repeated failed trims; capacity edge refuses before dispatch while admitted requests still write full records.
- Acceptance measurement per committed trim at 1x and 10x: bytes read/written, entries examined, sync latency, longest event-loop stall, beside the ordered-row equality check.
